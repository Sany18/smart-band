# Заміна голосового асистента (XiaoAI) — Mi Fitness 3.56.0

Шляхи нижче — відносно `work/jadx/sources/com/xiaomi/fitness/aivs/` (декомпільований код, у git не входить).

## Як це працює зараз (перевірено в коді)

1. Браслет надсилає BLE-пакет `type == 103` → `init/AivsComponent.java:112-143`.
   Фіча вмикається, лише якщо `isSupportFeature(model, "xiaoai")` (рядок 119).
2. Кадри: `bluetooth/AivsCommand.java:39-66` — байт 0 = версія, далі команда:
   `1=START` (data[0]=sessionId, data[1]=ttsMode), `2=AUDIO_DATA`, `3=END`, `4=QUIT`.
3. Аудіо: **Opus, 16 кГц, моно**. Декодується в PCM у
   `bluetooth/BluetoothEventSession.java:29,45-75` (`new OpusDecoder(16000,1,240,80)`).
4. PCM іде в хмарний SDK Xiaomi (`com.xiaomi.ai.android.core.Engine`),
   авторизація — OAuth client-credentials (`base/BaseAivsService.java:457-470, 579-590`).
5. Відповідь повертається на браслет через
   `bluetooth/BluetoothInstructionCapabilityImpl.process()` (рядок 1617) →
   `BluetoothAivsService.sendAivsInstruction(n21)` (`bluetooth/BluetoothAivsService.java:126-138`).

Коди інструкцій `n21.c`, які бачить браслет:

| Код | Що це | Поле |
|---|---|---|
| 2 | розпізнаний текст запиту (ASR) | `e` (v31) |
| 264 | «озвучений» текст відповіді, обрізається до 300 символів | `n` (x31) |
| 290 | текстова відповідь LLM | `G` (d31.c) |
| 293 | кінець потоку | — |

Звук TTS **на браслет не передається** — лише текст; аудіо грається на BT-гарнітуру телефона.

## Чому він «китайський»

Застосунок **не передає** ні локаль, ні часовий пояс в AIVS
(`Settings.ClientInfo.setTimeZone/setLocale` ніде не викликаються). Синхронізація часу
з браслетом окремо бере `TimeZone.getDefault()` телефона — примусового Asia/Shanghai
не знайдено. Тобто китайська мова і китайський час — це поведінка **хмари XiaoAI**, а не
браслета. Виправити налаштуванням не вийде; треба підміняти бекенд.

## План заміни

Точка перехоплення — `BluetoothInstructionCapabilityImpl`:

- **Варіант A (простіший):** брати сирий PCM у `base/BaseEventSession.run` (рядок ~154),
  відправляти у власний сервіс розпізнавання + LLM (наприклад, Claude з
  українською мовою і часовим поясом Europe/Kyiv), а відповідь слати на браслет як
  `n21{c=290, G.c="<текст>"}` і завершувати `c=293`. Хмару Xiaomi не викликати зовсім.
- **Варіант B:** лишити ASR Xiaomi (він розпізнає лише китайську — для нас марно). Тому A.

Що треба перевірити на залізі:
- чи шрифт прошивки n67cn показує кирилицю/латиницю у відповіді (з коду не видно);
- чи браслет не чекає обов'язкового коду 2 (ASR) перед відповіддю.

Альтернатива без патча APK: реалізувати той самий протокол (`type 103`, Opus 16 кГц,
інструкції `n21`) у форку Gadgetbridge — там уже є вся BLE-інфраструктура.
